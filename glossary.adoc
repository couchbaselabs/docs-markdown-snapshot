= Couchbase Glossary

This glossary provides definitions for key terms, technologies, and concepts used throughout the Couchbase documentation. Definitions are extracted from the actual Couchbase documentation with links to source material.

== A

*ACID (Atomicity, Consistency, Isolation, Durability)*:: Operations that ensure that when multiple documents need to be modified such that only the successful modification of all justifies the modification of any, either all the modifications do occur successfully; or none of them occurs. See link:/server/current/learn/data/transactions.md[Distributed ACID Transactions] for more details.

*Active Replicator*:: The Sync Gateway endpoint that initiates the replication connection - where the replicators are configured and from which changes are pushed. Synonym: active sync gateway. See link:/sync-gateway/current/glossary.md#active-replicator[Sync Gateway Glossary].

*Active Sync Gateway Node*:: Sync Gateway nodes with incoming writes from Couchbase Lite clients, REST API, or through Couchbase Server. See link:/sync-gateway/current/glossary.md[Sync Gateway Glossary].

*Adhoc Replication*:: Transient, one-shot replications that run once and are removed when they stop. Initialized using the Admin REST API, useful for one-off replication or troubleshooting. See link:/sync-gateway/current/glossary.md#adhoc-replication[Sync Gateway Glossary].

*Agentic App*:: An application that uses a Large Language Model (LLM) to simulate reasoning, planning, and decision-making. These apps are goal-oriented, can execute autonomously, use multi-step reasoning, and interact with external services and APIs. See link:/ai/agent-tutorial/about-agentic-app.md[About Agentic Apps].

*Agent Catalog*:: Couchbase service that helps manage tools and prompts for custom AI agents, using your preferred LLM and agent framework. See link:/ai/build/integrate-agent-with-catalog.md[Agent Catalog].

*Agent Framework*:: Provides reusable building blocks and patterns for building agentic apps, including prompt management, memory handling, tool integration, orchestration, and guardrails. See link:/ai/agent-tutorial/plan-agentic-app.md[Agent Development Framework].

*Agent Tracer*:: A tool in Capella AI Services for monitoring and observing agent activity, adding spans and callbacks, viewing traces, and querying traces with SQL++. See link:/ai/build/agent-tracer/agent-tracer.md[Agent Tracer].

*Analytics Service*:: Supports join, set, aggregation, and grouping operations that are expected to be large, long-running, and highly consumptive of memory and CPU resources. See link:/python-sdk/current/howtos/analytics-using-sdk.md[Analytics SDK Documentation].

*Analytics SDK*:: Client SDKs provided by Couchbase for connecting applications to the Analytics Service to execute analytical queries. See link:/dotnet-analytics-sdk/current/hello-world/overview.md[.NET Analytics SDK].

*App Endpoint*:: An endpoint in Capella App Services that exposes a database to client applications with synchronization capabilities. See link:/app-services/app-endpoints/about-app-endpoints.md[About App Endpoints].

*App Role*:: A role defined in Capella App Services that determines access grants assigned to users. Admin channels can be specified per collection. See link:/app-services/security/create-app-role.md[Create App Role].

*App Service*:: A fully managed application backend designed for mobile and edge applications, using Couchbase Lite embedded database for local storage and sync. See link:/app-services/get-started/configuring-app-services.md[Capella App Services].

*App User*:: A user in Capella App Services that can be assigned roles and channels, allowing access to specific data collections. See link:/app-services/security/create-user.md[Create App User].

== B

*Backup*:: Allows the scheduling of backups and merges of data. See link:/server/current/learn/services-and-indexes/services/backup-service.md[Backup Service].

*Bucket*:: A logical, user-named entity that groups items; allowing them to be accessed, indexed, replicated, and access-controlled. There are two types: **Couchbase** (retains data both in memory and on disk) and **Ephemeral** (retains data in memory only). See link:/server/current/learn/buckets-memory-and-storage/buckets.md[Buckets].

*Bucket alias*:: A bucket alias binding gives the JavaScript of an Eventing Function access to the Couchbase KV collections from the Data Service or KV. See link:/server/current/eventing/eventing-Terminologies.md#bucket-alias[Eventing Bucket Alias].

== C

*CAS (Compare and Swap)*:: A value which is altered each time a document is mutated. Used in Concurrent Document Mutations for a type of optimistic locking. See link:/python-sdk/current/howtos/concurrent-document-mutations.md[CAS and Concurrent Document Mutations].

*Capella*:: Couchbase's cloud-based database-as-a-service platform that provides SQL-like querying, Full-Text Search, vector search, eventing, and mobile sync capabilities. See link:/cloud/get-started/intro.md[Welcome to Couchbase Capella].

*Capella AI Services*:: Services that provide tools to create agentic and retrieval-augmented generation (RAG) AI applications, integrating seamlessly with Couchbase Capella cloud platform. Includes Model Service, Workflows, Agent Catalog, and AI Functions. See link:/ai/get-started/intro.md[Capella AI Services].

*Capella AI Functions*:: Functions to summarize text, classify content, detect sentiment, explain patterns, and more — all within SQL++ queries. See link:/ai/build/ai-functions.md[Capella AI Functions].

*Capella Analytics*:: A JSON-native NoSQL analytical database with GenAI capabilities, enabling real-time analytics without ETL transformation complexities. Features column-oriented storage, MPP computation engine, and Zero ETL capabilities. See link:/analytics/intro/intro.md[Capella Analytics Introduction].

*Capella Analytics SDK*:: SDKs for the Java, Node.js, and Python platforms specifically for Capella Analytics. See link:/analytics/sqlpp/1_intro.md[Capella Analytics SDKs].

*Capella Model Service*:: Service to deploy and manage Large Language Models (LLMs) and embedding models in Capella to power AI-driven applications. See link:/ai/build/model-service/model-service.md[Model Service].

*Capella iQ*:: Conversational coding feature using a Large Language Model (LLM) for SQL++ development, allowing natural language SQL++ query creation. See link:/analytics/query/iq.md[Capella iQ].

*Certificate Authentication (Cert Auth)*:: A client attempting to access Couchbase Server can present a certificate to the server, allowing the server to check the validity of the certificate. If the certificate is valid, the user under whose identity the client is running, and the roles assigned that user, are verified. Available in Capella and Enterprise Edition only. See link:/python-sdk/current/howtos/sdk-authentication.md#certificate-authentication[Certificate Authentication].

*Channels*:: In App Services, a mechanism for partitioning data access, similar to tags, allowing users to subscribe to specific subsets of data. See link:/app-services/security/channels.md[Manage Channels].

*Checkpoint*:: In Sync Gateway, a "save state" on a replicator used to enable a restart at the last success-point in the event of a failure during replication. See link:/sync-gateway/current/glossary.md#checkpoint[Checkpoint].

*Chronicle*:: The Couchbase-Server methodology for consensus-based metadata management, based on the link:https://raft.github.io/[Raft] algorithm. See link:/server/current/learn/clusters-and-availability/metadata-management.md[Chronicle and Metadata Management].

*Cloud-to-Edge Sync*:: Multi-cloud deployment mode known as ship-to-shore or hub-and-spoke, involving many edge clusters connected to cloud data centers. See link:/sync-gateway/current/glossary.md[Sync Gateway Glossary].

*Cloud-to-Edge Synchronization*:: Scenarios involving a hierarchy of Couchbase mobile clusters where edge clusters synchronize data changes with cloud data centers. See link:/sync-gateway/current/glossary.md[Sync Gateway Glossary].

*Cluster*:: One or more instances of Couchbase Server, each running on an independent node; but cooperating with any and all others, so as to form a unified system; whereby resources are shared, and a single interface provided for data-access and management. See link:/server/current/learn/clusters-and-availability/clusters-and-availability.md[Clusters and Availability].

*Cluster Provisioning*:: The primary means for managing clusters is through the Couchbase Web UI which provides an easy to use interface for adding, removing, monitoring and modifying buckets. The SDK also comes with some convenience functionality for common Couchbase management requests. See link:/python-sdk/current/howtos/provisioning-cluster-resources.md[Provisioning Cluster Resources].

*Collection*:: A data container, defined on Couchbase Server, within a bucket whose type is either Couchbase or Ephemeral. From Server 7.0, Collections allow groupings of documents beneath the Bucket level. See link:/python-sdk/current/concept-docs/collections.md[Collections].

*Column-Oriented Storage*:: Storage engine in Capella Analytics built to expand analytic performance and capacity, storing data in cloud object stores separated from computation features. See link:/analytics/intro/intro.md[Capella Analytics Architecture].

*Constant alias*:: A constant alias is used by the JavaScript code of the Eventing Function as a global variable. The value can be an integer, a decimal number, a string, a boolean, or a JSON object. See link:/server/current/eventing/eventing-Terminologies.md#constant-alias[Eventing Constant Alias].

*Conflict Resolver Policies*:: Inter-Sync Gateway replication provides predefined policies: default (automatic timestamp-based), localWins, remoteWins, and custom (Enterprise only). See link:/sync-gateway/current/glossary.md[Conflict Resolver Policies].

*Custom Conflict Resolver*:: A Javascript function used to resolve conflicting changes in Inter-Sync Gateway replication (Enterprise Edition only). See link:/sync-gateway/current/glossary.md[Custom Conflict Resolver].

*Continuous Replication Mode*:: A continuous replication sits in a running state awaiting document changes to process in accordance to its replication definition. See link:/sync-gateway/current/glossary.md[Continuous Replication].

*CreateTimer*:: A built-in function call in Eventing that creates a Timer to schedule functions to run in the future. See link:/server/current/eventing/eventing-Language-Constructs.md#createtimer-function[createTime Function Call].

*Custom Transcoders*:: Whenever key-value data is sent to or retrieved from Couchbase Server, the SDK passes the data being sent to a transcoder. The transcoder can either reject the data as being unsupported, or convert it into a byte array and a Common Flag. More advanced transcoding needs can be accomplished if the application implements their own transcoders and serializers. See link:/python-sdk/current/howtos/transcoders-nonjson.md[Transcoders and Non-JSON Documents].

== D

*Data*:: Items, each of which consists of a key by which the item is referenced; and an associated value, which must be either binary or a JSON document. See link:/server/current/learn/data/data.md[Data Model].

*Data Service*:: Supports the storing, setting, and retrieving of data-items, specified by key. See link:/server/current/learn/services-and-indexes/services/data-service.md[Data Service].

*DCP (Database Change Protocol)*:: The protocol used to stream bucket-level mutations. DCP is used for high-speed replication of mutations; to maintain replica vBuckets, incremental MapReduce and spatial views, Global Secondary Indexes (GSIs), XDCR, backups, and external connections. See link:/server/current/learn/clusters-and-availability/intra-cluster-replication.md#database-change-protocol[Database Change Protocol].

*Deduplication*:: To ensure high performance, the KV data engine deduplicates multiple mutations made to an individual document in succession. Handlers might not see all intermediate states of a document when it mutates quickly, but they do see its final state. See link:/server/current/eventing/eventing-Terminologies.md#deduplication[Eventing Deduplication].

*Deployment*:: The installation of a single instance of Couchbase Server, subsequent to the appropriate resourcing and configuration of an underlying platform. Can be Cloud (runs on a pre-established cloud-configuration), Container (runs within a software container or virtual machine), or Native (runs on an individual, physical machine). See link:/server/current/install/get-started.md[Deployment].

*Document*:: An item in Couchbase consisting of a key by which the item is referenced; and an associated value, which must be either binary or a JSON document. See link:/python-sdk/current/concept-docs/documents.md[Documents].

*Durable Writes*:: See link:/server/current/learn/data/durability.md[Durability] - The atomic commitment of a single-document data-write, which ensures the write's greatest likelihood of surviving an unexpected anomaly, such as a node-outage, prior to the write's propagation throughout the entire cluster.

*Durability*:: Couchbase Server 6.0 and earlier, with 2.x API versions of the SDK, used Observe style durability. All current, supported versions of Couchbase Server offer Server-side DurableWrites. See link:/python-sdk/current/concept-docs/durability-replication-failure-considerations.md[Durability and Replication].

== E

*Ephemeral Bucket*:: A bucket type that retains data in memory only. See link:/server/current/learn/buckets-memory-and-storage/buckets.md[Buckets].

*Eventing Function*:: Standalone JavaScript fragments that trigger in real time as a response to document mutations and must be executed from start to finish before the specified timeout. See link:/server/current/eventing/eventing-Terminologies.md[Eventing Terminologies].

*Eventing Service*:: Supports near real-time handling of changes to data: code can be executed both in response to document-mutations, and as scheduled by timers. See link:/server/current/eventing/eventing-overview.md[Eventing Service].

*Eventing Storage*:: The Eventing Function's metadata bucket. The metadata bucket stores artifacts, or configuration documents, that contain information about DCP streams, worker allocations, Timer information and state, and internal checkpoints. See link:/server/current/eventing/eventing-Terminologies.md#eventing-storage[Eventing Storage].

*Eventing Keyspaces*:: A keyspace is a path to a collection in the format `bucket-name.scope-name.collection-name`. The two keyspaces used by Eventing Functions are Listen to Location (the Eventing source) and Eventing Storage (the Eventing metadata). See link:/server/current/eventing/eventing-Terminologies.md#eventing-keyspaces[Eventing Keyspaces].

*Extended Attributes*:: See link:/python-sdk/current/howtos/subdocument-operations.md#extended-attributes[XATTRs] - Extended Attributes (XATTRs), built upon the Sub-Document API, allow developers to define application-specific metadata that will only be visible to those applications that request it or attempt to modify it.

== F

*Failover*:: The ability to allow healthy nodes to continue functioning as a cluster, potentially without data-loss, when one node has gone offline. Rebalance ensures that data, indexes, event processing and query processing are optimally distributed across all available nodes. See link:/server/current/learn/clusters-and-availability/failover.md[Failover].

*Field Level Encryption (FLE)*:: Encryptrion of the field or value in a key-value pair, using a FIPS-140-2 compliant cryptography algorithm. See link:/python-sdk/current/concept-docs/encryption.md[Field Level Encryption].

*Full Text Search (FTS)*:: Create, manage, and query full-text indexes on JSON documents stored in Couchbase buckets. FTS uses natural language processing for indexing and querying documents, provides relevance scoring on the results of your queries, and has fast indexes for querying a wide range of possible text searches. Also integrates with Vector Search indexes. See link:/python-sdk/current/howtos/full-text-searching-with-sdk.md[Full Text Search].

*Function Scope*:: You can use a `bucket.scope` to identify Functions that belong to the same group. See link:/server/current/eventing/eventing-Terminologies.md#function-scope[Eventing Function Scope].

== G

*Global Secondary Indexes (GSI)*:: A Global Secondary Index (GSI) supports queries made by the Query Service on attributes within documents. Secondary indexes — which contain a filtered or a full set of keys in a given bucket — are optional, but increase query efficiency on a bucket. See link:/server/current/learn/services-and-indexes/indexes/indexing-overview.md[Global Secondary Indexes].

== H

*Handlers*:: The Eventing Service calls the OnUpdate, OnDelete, and Timer Callback handlers on mutations and fired timers. See link:/server/current/eventing/eventing-Terminologies.md#handlers[Eventing Handlers].

=== OnUpdate
The OnUpdate handler is called when you create or modify a document. The entry point OnUpdate(doc,meta) passes doc, the document, and meta, which contains additional data like the document ID, CAS, expiration date, and data type.

=== OnDelete
The OnDelete handler is called when you delete a document or when the document expires. The entry point OnDelete(meta,options) passes meta, which contains information like the document, and options, that contains the boolean parameter options.expired that indicates if the document was removed because of a deletion or an expiration.

=== OnDeploy
The OnDeploy handler runs once when an Eventing function is deployed or resumed, before any mutations are processed. See link:/server/current/eventing/eventing-Terminologies.md#ondeploy[OnDeploy Handler].

== I

*Index Service*:: Creates indexes, for use by the Query Service. See link:/server/current/learn/services-and-indexes/services/index-service.md[Index Service].

*Initialization*:: The configuration of a new instance of Couchbase Server, either as the first node in a new cluster, or as an additional node for an existing cluster. See link:/server/current/manage/manage-nodes/initialize-node.md[Node Initialization].

== K

*Key-Value Operations (KV Operations)*:: KV Operations work directly on the document, for CRUD operations on documents whose identity (key) is known. The Data (KV) Service uses a fast binary protocol, and is often the best choice for optimum performance. See link:/python-sdk/current/howtos/kv-operations.md[Key-Value Operations].

*Keyspace*:: A path to a collection in the format `bucket-name.scope-name.collection-name`. See link:/server/current/eventing/eventing-Terminologies.md#eventing-keyspaces[Eventing Keyspaces].

== L

*Listen to Location*:: Eventing Functions use a collection as the source for their data mutations. This collection is called the Eventing source, and can be made up of Couchbase or Ephemeral keyspace types. See link:/server/current/eventing/eventing-Terminologies.md#listen-to-location[Eventing Listen to Location].

== M

*MapReduce Views*:: MapReduce Views uses distributed Map-Reduce for very fast aggregation operations (fast, because the indexes are pre-computed results) — ideal for pre-grouped aggregations, such as grouping temporal data sets (by day, by month, etc.). However, Views are deprecated in the latest versions of Couchbase Server, and will eventually be removed. See link:/python-sdk/current/howtos/view-queries-with-sdk.md[MapReduce Views].

*Memory*:: An automatically managed caching layer, supporting high-speed data-access. See link:/server/current/learn/buckets-memory-and-storage/memory.md[Memory].

== N

*Node*:: A computer (potentially, a virtual machine) running an instance of Couchbase Server. See link:/server/current/learn/clusters-and-availability/nodes.md[Nodes].

*Node Addition*:: The ability to add a Couchbase Cluster of one node to another existing cluster, so that a single, combined cluster is produced. See link:/server/current/manage/manage-nodes/add-node-and-rebalance.md[Add Node].

*Node Removal*:: The ability to remove a node from a cluster. Following removal, rebalance ensures that data, indexes, event processing and query processing are optimally distributed across all available nodes. See link:/server/current/manage/manage-nodes/remove-node-and-rebalance.md[Remove Node].

*N1QL*:: See link:/python-sdk/current/howtos/n1ql-queries-with-sdk.md[SQL++] - The Couchbase Query Service uses a SQL-like language for powerful queries across documents.

== O

*Operations*:: Operations in Eventing: Deploy, Undeploy, Pause, Resume, Delete, and Debug. See link:/server/current/eventing/eventing-Terminologies.md#operations[Eventing Operations].

== P

*RBAC (Role-Based Access Control)*:: Role-Based Access Control allows secure, fine-grained access privileges, assigned to fixed roles. The 3.x API allows some user management programmatically from the SDK. See link:/server/current/learn/security/authorization-overview.md#introduction-to-rbac[RBAC].

== Q

*Query*:: The Couchbase Query Service parses input specified in the N1QL query-language, executes queries, and returns results. The Query Service interacts with both the Data and Index services. See link:/server/current/learn/services-and-indexes/services/query-service.md[Query Service].

*Query Service*:: See link:/server/current/learn/services-and-indexes/services/query-service.md[Query].

== R

*Recursive Mutation*:: A potentially recursive mutation happens when a handler manipulates documents in a keyspace that also serves as the mutation source for this or another handler. The write originated by the handler causes a mutation to be seen by itself or by another handler. See link:/server/current/eventing/eventing-Terminologies.md#recursive-mutation[Eventing Recursive Mutation].

*Rebalance*:: The process of redistributing data, indexes, event processing, and query processing optimally among the available nodes of a cluster. This should be performed whenever a cluster-configuration has changed. See link:/server/current/learn/clusters-and-availability/rebalance.md[Rebalance].

*Recursive Mutation*:: A potentially recursive mutation happens when a handler manipulates documents in a keyspace that also serves as the mutation source. See link:/server/current/eventing/eventing-Terminologies.md#recursive-mutation[Recursive Mutation].

== S

*Scaling*:: The optional allocation of services to cluster-nodes in accordance with workload-requirements. For example, if a particular service is expected to handle a heavy workload, it can be allocated a large memory quota, and might be deployed as the only service on its node. See link:/server/current/learn/services-and-indexes/services/services.md[Multi-Dimensional Scaling].

*SDK*:: Libraries that support cluster-access for applications written in multiple languages. See link:/server/current/learn/data/data.md#access[SDK Access].

*Scope*:: A mechanism for the grouping of multiple collections. From Server 7.0, Collections allow groupings of documents beneath the Bucket level, and Scopes group together Collections. Applications can be assigned per-scope access rights. See link:/python-sdk/current/concept-docs/collections.md[Scopes and Collections].

*Search Service*:: Creates indexes specially purposed for Full Text Search. This supports language-aware searching; allowing users to search for, say, the word beauties, and additionally obtain results for beauty and beautiful. See link:/cloud/search/search.md[Search Service].

*Server*:: An instance of Couchbase Server — an open source, distributed, NoSQL document-oriented engagement database, specialized to provide low-latency data management for large-scale interactive web, mobile, and other applications. See link:/server/current/learn/introduction/intro.md[Couchbase Server Introduction].

*SQL++*:: Couchbase's powerful SQL-like language (formerly N1QL) allows queries in a format familiar to Database Administrators. These can be made against our Query Service, for transaction (OLTP) queries, or against our analytics (OLAP) services — CBAS or, for real-time analytics, Capella Columnar. See link:/python-sdk/current/concept-docs/n1ql-query.md[SQL++ Language Reference].

*SQL++ for Capella Analytics*:: An extension of the SQL++ grammar, statements, and capabilities used with the Analytics Service in Couchbase Server and Capella, focused on parallel data analysis. See link:/analytics/sqlpp/1_intro.md[SQL++ for Capella Analytics Introduction].

*SQL++ Features*:: Includes expanded entity hierarchy, syntax for creating standalone collections, and new DML/DML statements for analytics operations. See link:/analytics/sqlpp/1_intro.md#features[SQL++ for Capella Analytics Features].

*Statelessness*:: The persistent state of an Eventing Function is captured in external elements: Documents or mutations and their extended attributes, Eventing Storage (metadata), and optional bindings. See link:/server/current/eventing/eventing-Terminologies.md#statelessness[Eventing Statelessness].

*Storage*:: The persistent retention of items on disk, in compressed form, with high-speed threaded access. See link:/server/current/learn/buckets-memory-and-storage/storage-settings.md[Storage Settings].

*Sub-Document Operations*:: Sub-Document retrievals only retrieve relevant parts of a document and Sub-Document updates only require sending the updated portions of a document. Sub-Document operations are also atomic, in that if one Sub-Document mutation fails then all will, allowing safe modifications to documents with built-in concurrency control. See link:/python-sdk/current/howtos/subdocument-operations.md[Sub-Document Operations].

== T

*Timeout*:: Eventing Functions have a Script Timeout (number of seconds before the script times out and terminates) and OnDeploy Timeout (number of seconds before the OnDeploy entry point times out and terminates). See link:/server/current/eventing/eventing-Terminologies.md#function-settings[Eventing Function Settings].

*Timer*:: A mechanism in Eventing to schedule functions to run in the future. See link:/server/current/eventing/eventing-timers.md[Eventing Timers].

*Timer Callback*:: Timer callbacks are user-defined JavaScript functions passed as the callback argument to the built-in function call createTimer(callback,date,reference,context). See link:/server/current/eventing/eventing-Terminologies.md#timer-callback[Timer Callback].

*Tools*:: Provided by Couchbase Server to support cluster-management: CLI (Command-line-based management), Couchbase Web Console (UI-based management), and REST API (RESTful management). See link:/server/current/manage/management-overview.md#couchbase-server-tools[Server Management Tools].

*Transactions*:: Operations that ensure that when multiple documents need to be modified such that only the successful modification of all justifies the modification of any, either all the modifications do occur successfully; or none of them occurs. See link:/python-sdk/current/howtos/distributed-acid-transactions-from-the-sdk.md[Distributed ACID Transactions].

== U

*URL alias*:: A URL alias binding is used by the cURL language construct to access external resources. The URL alias specifies the endpoint, the HTTP/S protocol, and the credentials. See link:/server/current/eventing/eventing-Terminologies.md#url-alias[Eventing URL Alias].

== V

*Vector Search*:: With Couchbase Vector Search, you can enable fast and highly accurate semantic search, ground LLM responses in relevant data to reduce hallucinations, and enhance or enable use cases like personalized searches in e-commerce and media & entertainment, product recommendations, fraud detection, and reverse image search. See link:/python-sdk/current/howtos/vector-searching-with-sdk.md[Vector Search].

*Virtual Extended Attributes (VIRTUAL XATTRs)*:: Virtual Extended Attributes (VXATTR) consist of metadata on an individual document, generated on-demand to expose storage-level document metadata, such as expiry to expose document expiration. See link:/python-sdk/current/concept-docs/xattr.md#virtual-extended-attributes[Virtual Extended Attributes].

== X

*XATTRs (Extended Attributes)*:: Extended Attributes (XATTRs), built upon the Sub-Document API, allow developers to define application-specific metadata that will only be visible to those applications that request it or attempt to modify it. They are not intended for use in general applications, and data stored there cannot be accessed easily by some Couchbase services, such as Search. See link:/python-sdk/current/howtos/subdocument-operations.md#extended-attributes[Extended Attributes].

*XDCR (Cross Data Center Replication)*:: The replication of data between clusters, to ensure the least chance of data-loss in the event of data-center failure, and to provide high-performance data-access for globally distributed applications. See link:/server/current/learn/clusters-and-availability/xdcr-overview.md[Cross Data Center Replication].

== Additional References

*Intra-Cluster Replication*:: The maintenance and continuous update of data-copies, distributed across the nodes of a cluster, to ensure the least chance of data-loss in the event of single-node failure. See link:/server/current/learn/clusters-and-availability/intra-cluster-replication.md[Intra-Cluster Replication].

*Data Recovery*:: The restoration of current data to a node that is recovered from failure: either by updating data still held locally, or by substituting current data from other nodes. See link:/server/current/cli/cbcli/couchbase-cli-recovery.md[Data Recovery].

== Additional Terms from AI Services, Analytics, and Sync Gateway

*Embedding Model*:: A machine learning model that converts text or data into dense vector representations for similarity search. See link:/ai/build/model-service/deploy-embed-model.md[Deploy an Embedding Model].

*Grafana*:: An open source data visualization and alerting platform that supports Prometheus as a data source and can be used to build comprehensive dashboards. See link:/sync-gateway/current/glossary.md[Grafana].

*Guardrails*:: Ways to enforce rules, validate tool calls, and keep the agent within safe boundaries in agentic apps. See link:/ai/build/model-service/configure-guardrails-security.md[Configure Guardrails].

*Leaf Revision*:: The last Document Revision in a series of changes. Documents may have multiple Leaf Revisions (aka Conflict Revisions) due to concurrent updates. See link:/sync-gateway/current/glossary.md[Leaf Revision].

*Large Language Model (LLM)*:: A machine learning model trained on vast amounts of text data that can generate and understand natural language, used as a reasoning engine in agentic apps. See link:/ai/build/model-service/deploy-llm-model.md[Deploy an LLM].

*Memory (in Agentic Apps)*:: Information required by the LLM to make decisions, passed through the prompt. Two main forms: Short-term memory (current conversation or task state) and long-term memory (knowledge, past results, and context). See link:/ai/agent-tutorial/about-agentic-app.md#the-memory[Agentic App Memory].

*MPP-Based Computation Engine*:: Massively parallel processing computation engine in Capella Analytics allowing real-time calculations regardless of data size. See link:/analytics/intro/intro.md[Capella Analytics Architecture].

*No Conflicts Mode*:: Process where write operations that would result in a conflict are rejected by the system. Configured using the allow_conflicts property. See link:/sync-gateway/current/glossary.md[No Conflicts Mode].

*No Op Updates*:: A change made to the document body that does not impact application logic but does trigger replication by Sync Gateway. See link:/sync-gateway/current/glossary.md[No Op Updates].

*One-Shot Replication Mode*:: A one-shot replication will start, process all existing document changes and then stop. See link:/sync-gateway/current/glossary.md[One-Shot Replication].

*Orchestration Layer*:: The glue between the LLM and the rest of the app that manages the prompt, decides when to call external tools, injects retrieved knowledge, applies guardrails, and handles retries. See link:/ai/agent-tutorial/about-agentic-app.md#the-orchestration-layer[Agentic App Orchestration Layer].

*Passive Replicator*:: The Sync Gateway endpoint that receives an incoming replication connection. See link:/sync-gateway/current/glossary.md[Passive Replicator].

*Persistent Exponential Backoff*:: The wait time between retry attempts is exponentially increased at each attempt, until it reaches a predetermined maximum limit. See link:/sync-gateway/current/glossary.md[Persistent Exponential Backoff].

*Persistent Replication*:: Replications that survive Sync Gateway restarts, defined in the configuration file sync-gateway.json. The recommended method of defining persistent replication is by using the configuration file. See link:/sync-gateway/current/glossary.md[Persistent Replication].

*Prompts*:: How you tell the LLM what role it's playing, how it should behave and what information it has available. A constructed input assembled by the orchestration layer that grows and changes as the app progresses through its workflow. See link:/ai/agent-tutorial/about-agentic-app.md#the-prompts[Agentic App Prompts].

*Prometheus*:: An open source systems monitoring and alerting platform with the Prometheus Server responsible for polling Prometheus targets for stats and storing as time series data. See link:/sync-gateway/current/glossary.md[Prometheus].

*RAG (Retrieval-Augmented Generation)*:: A pattern for building AI applications that combines retrieval of relevant data with LLM generation to produce contextually relevant responses. See link:/ai/agent-tutorial/rag-patterns.md[RAG Blueprints].

*Replication Definition*:: The set of elements (parameters or properties) that define a replication, dictating what will be replicated and how the replication will be conducted. See link:/sync-gateway/current/glossary.md[Replication Definition].

*Revision Pruning*:: The process that deletes the metadata and/or JSON bodies associated with old non-leaf revisions. Leaf revisions are not impacted. See link:/sync-gateway/current/glossary.md[Revision Pruning].

*Reranking*:: Hyperscale Vector Index feature for reranking vector search results for improved accuracy. See link:/cloud/vector-index/hyperscale-reranking.md[Hyperscale Vector Index Reranking].

*SQL++ Expressions*:: The different types of SQL++ expressions including literal values, identifiers, arithmetic terms, comparison terms, concatenation terms, logical terms, conditional expressions, collection expressions, construction expressions, subqueries, and function calls. See link:/cloud/n1ql/n1ql-language-reference/index.md[SQL++ Language Reference].

*SQL++ Statements*:: Categorized into Data Definition Language (DDL), Data Control Language (DCL), and Data Manipulation Language (DML) statements. See link:/cloud/n1ql/n1ql-language-reference/index.md[SQL++ Statements].

*Search Index*:: Tells the Search Service what content to use from the documents for processing Search queries. Can use any field across multiple collections in a single scope. See link:/cloud/search/search.md[Search Index].

*Search Query*:: Tells the Search Service what to search for in the contents of a Search index. Uses string-based query syntax or JSON objects to control result retrieval. See link:/cloud/search/search.md[Search Queries].

*Standalone Collection*:: A collection in Capella Analytics for columnar storage, optimized for analytical workloads. See link:/analytics/sources/manage-columnar.md[Standalone Collection].

*Synchronization*:: The process of replicating the changes made to documents on one database to the same documents in a second instance of that database. Synonyms: replication, sync. See link:/sync-gateway/current/glossary.md[Synchronization].

*Sync Function*:: A JavaScript function responsible for data validation and authorizing both read and write access to documents. See link:/sync-gateway/current/access-control/sync-function/sync-function.md[Sync Function].

*Sync Gateway Database*:: A namespace for documents that provides Sync Gateway with access to documents stored in Couchbase Server. See link:/sync-gateway/current/glossary.md[Sync Gateway Database].

*TAV (Tabular View)*:: A saved query result view in Capella Analytics for quick access and sharing. See link:/analytics/query/views-tavs.md[Views and Tabular Views].

*The LLM*:: Rather than a complex decision tree, agentic apps use a Large Language Model (LLM) as a reasoning engine that can take instructions and make decisions on how to proceed. See link:/ai/agent-tutorial/about-agentic-app.md#the-llm[Agentic App LLM].

*The Tools*:: The ways the agent interacts with other systems either within the app or the outside world, including APIs, databases, web searches, pre-written code functions, or other agents. See link:/ai/agent-tutorial/about-agentic-app.md#the-tools[Agentic App Tools].

*Tombstone Revision*:: A marker indicating that a document has been deleted, comprises document ID, revision ID and a _deleted flag (value=true). See link:/sync-gateway/current/glossary.md[Tombstone Revision].

*Tools (in Agentic Apps)*:: The ways the agent interacts with other systems either within the app or the outside world, including APIs, databases, web searches, pre-written code functions, or other agents. See link:/ai/agent-tutorial/about-agentic-app.md#the-tools[Agentic App Tools].

*Transient Replication*:: See Adhoc Replication - transient, one-shot replications that run once and are removed when they stop. See link:/sync-gateway/current/glossary.md[Transient Replication].

*Vector Index*:: An index that stores and searches vector embeddings, enabling AI-powered similarity searches. See link:/cloud/vector-index/vectors-and-indexes-overview.md[Vector Index].

*Vectorization*:: The process of converting text or data into vector representations for similarity search. See link:/ai/build/vectorization-service/data-processing.md[Vectorization Service].

*Zero ETL*:: Elimination of ETL transformation complexities by unifying operational and analytical data stores into a single platform. See link:/analytics/intro/intro.md[Capella Analytics Zero ETL].
